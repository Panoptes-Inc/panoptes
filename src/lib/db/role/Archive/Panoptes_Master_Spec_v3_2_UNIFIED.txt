1. Product Definition
1.1 Panoptesとは何か
Panoptesは、
「競合・業界・自社の構造を読み、戦略を可視化し、実行優先順位まで導く戦略OS」
である。

Panoptesは以下ではない
- トラフィック推定ツール
- アナリティクスツール
- Similarweb系
- SEOツール
- LP改善ツール

Panoptesは以下である
- 構造理解装置
- 因果説明装置
- 戦略提案装置
- 実行優先順位エンジン
- 思考圧縮UI
- 戦略OS

1.2 MVPの目的
- URL入力から、競合・業界・自社の構造分析を実行する
- Internal / Visual の2レイヤーで6軸評価を行う
- 同格比較を軸に競合10社を分析する
- 業界構造を推定する
- 自社の差分と改善余地を示す
- 戦略提案3件を生成する
- 30/60/90日プランを task 管理付きで生成する
- snapshot として保存し、再分析で更新できるようにする

1.3 MVPでやらないこと
- 流入流出推定
- 滞在時間推定
- CVR推定
- 広告チャネル分析
- 指名検索推定
- GA / Search Console 統合
- Panoptes独自タグによる行動収集
- リアルタイム更新
- 自動改善実行
- 実行代行

2. MVP Absolute Rules
2.1 データ原則
MVPで使用するのは以下のみ
- サイトの内部構造
- サイトのビジュアル構造
- 競合比較ロジック
- Engine計算
- AIによる抽出と文章化

MVPで使用しない
- 外部推定データ
- アナリティクスデータ
- 流入/流出
- 滞在時間
- 属性推定
- 売上/市場シェア推定

2.2 観測レイヤー
Panoptesは常に以下の2レイヤーで観測する
- Internal
- Visual

2.3 戦略軸
固定6軸
- 価値訴求
- 情報階層
- 導線強度
- 信頼構造
- 差別化明確性
- 意思決定支援

2.4 LLM原則
LLMの役割
- 構造意味理解
- visual意味理解
- evidence整理
- narrative生成
- 提案文の文章化
- 戦略要約

LLMにやらせてはいけないもの
- スコア計算
- delta計算
- priority算出
- opportunity算出
- confidence算出
- coherence算出
- 業界平均計算
- 外部データ補完

2.5 保存原則
Panoptesは分析のたびに snapshot を保存する。
各タブは個別計算ではなく、同じ snapshot を参照して表示される。

2.6 API返却原則
APIは raw engine result を返さない。
返すのは以下のみ
- analysis job status
- snapshot view payload
- strategy state
- usage state

6. Crawling Architecture
6.1 クローリング方針
PanoptesはAIクローリングを行わない。
すべてのクロールは機械的クローリングで行う。
クローリングエンジンは Python crawler とする。

6.2 Crawl Modes
- bootstrap crawl
- analysis crawl
- monitoring crawl

6.3 bootstrap crawl
目的
- サイトの基本推定
- 業界
- サイトタイプ
- 構造タイプ
- 競合候補

対象
- top
- navリンク
- footerリンク
- 代表ページ

最大
- 10 pages

6.4 analysis crawl
目的
- 完全分析
- Internal evidence取得
- Visual evidence取得

対象
- 最大30ページ
- 優先: top / pricing / feature / faq / case / contact

6.5 monitoring crawl
目的
- 競合監視
- 差分検知
- Feed生成
- Radar生成

対象
- 主要ページのみ
- 最大10ページ

6.6 URL Discovery Rules

- 同一ドメイン
- HTMLページ
- nav / footer / CTA から辿れるページ

除外
- ログイン
- cart
- checkout
- session URL
- PDF
- 画像
- zip
- 外部リンク
- 検索ページ

URL正規化
- tracking削除
- fragment削除
- canonical優先
- duplicate除外

10. Unified Strategic Engine
10.1 6軸固定
内部キー
- value_proposition
- information_hierarchy
- navigation_strength
- trust_proof
- differentiation
- decision_support

10.2 Submetric
各軸は複数submetricで構成し、0.0〜1.0で評価する。
取得不能は null 許容。

10.3 Layer別スコア
各軸について
- internal_axis_score
- visual_axis_score
を算出する。

10.4 Layer総合
- internal_score
- visual_score

10.5 総合スコア
T = 1 / ((0.6 / I) + (0.4 / V))

10.6 Confidence調整

- c_visual

- c_delta
- c_total

10.7 Coherence補正

- delta_vs_competitor_set per axis

11. Strategy System
11.1 戦略提案の役割
戦略提案 = WHAT
30/60/90 = HOW / WHEN

11.2 戦略提案件数
MVPでは原則3件。

11.3 戦略カード構成
- title
- strategy_intent
- rationale
- action_items
- expected_impact

11.4 戦略カード制約
MVPで使わない
- CVR改善値
- 自然流入増加
- CPA改善
- 指名検索増加
- 広告効率改善

MVPで使う
- 導線強度スコア改善
- 信頼構造スコア改善
- 差別化明確性改善
- 意思決定支援改善
- 情報階層改善

11.5 strategy と phase task の責務
- strategy = 選択中の戦略テーマ
- phase plan = 30/60/90 の実行管理
- task = 各フェーズ内の具体タスク
- task transition = 状態変更履歴
- reanalysis merge = 再分析時の引き継ぎ判定

11.6 Selected Strategy State
保持項目

- source_snapshot_id
- selected_strategy_key
- selected_strategy_rank
- current_strategy_theme
- strategy_status
- previous_strategy_fit_index
- current_strategy_fit_index
- structural_risk_label
- improvement_headroom_percent

11.7 30/60/90
各 phase は実行管理単位とする。
phase plan 必須項目
- phase_key
- phase_label
- phase_theme
- phase_objective
- progress_status
- completed_task_count
- total_task_count
- assignee_status_label
- next_action
- tasks[]

task 必須項目
- task_key
- task_label
- task_status
- display_order

task_status
- not_started
- in_progress
- done
- blocked

11.8 Reanalysis relation
再分析時は strategy plan と phase task state を破壊しない。
判定
- strategy_keep
- strategy_update_recommended
- strategy_rework_required

task引き継ぎ
- exact / semantic / none
- obsolete task は archived 扱い
- new task は not_started で追加

12. Snapshot System

12.2 snapshot の役割

- self tab

14. API Contract
14.1 required API
- POST /api/project/create
- POST /api/project/select
- POST /api/analysis/start
- GET /api/analysis/:job_id
- GET /api/project/:project_id/dashboard
- POST /api/project/:project_id/strategy/select
- POST /api/project/:project_id/reanalyze
- POST /api/strategy/task/update-status
- GET /api/usage/current

14.2 request / response 基本方針
通信と保存は snake_case とする。

14.3 dashboard API
dashboard は SnapshotViewPayload を返す。
UIは engine 結果を再計算しない。

14.4 strategy API
- select strategy は current strategy の採用保存
- update phase task status は task状態だけ更新
- task transition は server側で自動記録

15. Security and Access Rules
15.1 access unit
org を基準とする。

15.2 read rule
同一 org の active member は project と snapshot を読める。

15.3 write rule
分析結果系テーブルは原則 server-only write。
クライアントから直接 insert / update させない。

15.4 admin
admin UI は URL 隠しではなく allowlist / role / server guard で制御する。

15.5 secrets
- service role key
- llm api keys
- crawler secrets
は server-side のみ保持する。

15.6 audit
重要操作は audit log に残す。
最低対象
- waitlist approval
- admin action
- project delete
- reanalysis trigger
- strategy selection
- task status change
